# Publisher routes

Read this file when institutional access or publisher-specific behavior affects a download. Route-selection guidance is adapted from InstSci; only sections explicitly marked ego-tested describe actual ego download evidence.

## Select an institutional route

1. Use the institution and entry route supplied by the user or established in the current task. Ask only if the required subscription institution cannot be resolved; a personal publisher login does not identify it.
2. Preserve a working route, including the current network connection and browser login. If a requested PDF is already accessible, download it without adding a login detour. If the user specified a school portal or VPN route, start with that route. With no established entry, inspect the public article in the current environment before selecting an institutional route.
3. When access is unresolved and no route was specified, inspect the article's `Institutional Access`, `Access through your organization`, Shibboleth, OpenAthens, or CARSI controls. Follow the actual institution search/selection flow, hand off credentials when needed, and apply [verification handling](diagnostic-guide.md#handle-webpage-verification) to webpage challenges. These are route candidates inherited from InstSci, not ego-tested publisher capabilities.
4. Use WebVPN when the user's institution provides it and the portal offers the relevant publisher. For an untested publisher, treat this as a trial route. A successful run establishes only the observed paper/session conditions.
5. If WebVPN fails without a security stop condition, inspect the visible error before trying an available article-page institutional route. Record both attempts. On explicit IP/account restrictions or repeated denial, follow the stop rules in `SKILL.md` instead of changing routes.

Record institution recognition, OA status, and article entitlement separately. A recognized institution can still lack access to a particular journal or year. An explicit subscription/access denial establishes that route's observed entitlement result; an unexplained 403 alone does not.

Network access and browser authentication are separate and may work together. Campus-network access may authorize a public publisher page; an institution's VPN client may provide that access through a network tunnel; WebVPN uses a portal and rewritten routes; retained portal or publisher authentication may still be needed in any of these environments. Preserve the user's working setup instead of imposing a universal direct-first or VPN-first order. Follow institution login only when current article access requires it. If a required network VPN is not connected, record that prerequisite and ask the user to connect it rather than treating a browser login as a substitute.

Record the observed public hosts, article access statement, reused authentication and user-reported network/VPN conditions separately; mark unconfirmed conditions as unknown. A canonical publisher URL can also be reached through a VPN tunnel. No WebVPN navigation or new login in a run does not prove that VPN was off or that IP alone supplied access. Do not clear the profile or disconnect a working VPN to manufacture that comparison.

## School WebVPN

Use the user's school library or WebVPN portal. The portal can rewrite both the article host and a separate PDF host; preserve the actual route it produces. An external proxy and school WebVPN may interact, but a failed paper request does not identify which component failed. Record the visible error before diagnosing network settings.

Keep institution domains and identity in the user's local run record rather than embedding a school-specific configuration in this reusable skill. An existing portal session may carry into a new TaskSpace because the profile is shared.

## GeoScienceWorld / Silverchair

Ego-tested with an existing school login: school WebVPN portal → GeoScienceWorld → search results or a previously observed article path → article → PDF popup on a Silverchair watermark host → browser PDF viewer → download. Evidence includes Economic Geology and GSA Bulletin articles, with ego-only recovery and file checks. These reused existing sessions; fresh institutional login and subscription-only entitlement remain unproven. For concurrent work, follow [parallel workflow](parallel-workflow.md).

- The institution menu may show recognition while personal `Sign In` remains available. These are separate login states.
- A PDF may live on another hostname and carry a short-lived signed query. Do not log that query or reuse it as a permanent article URL.
- A search filter may expose a navigation URL without triggering navigation. Inspect the rendered control and its actual destination before using that observed URL; do not guess private endpoints.
- In a WebVPN page, DOM `location` or an anchor's resolved `href` can point at the canonical publisher domain. Prefer clicking the visible link. If an observed relative destination must be resolved, use the browser API's current `page.url()` as the base and confirm the resulting route; this difference was observed during the serial trial.
- An accessible PDF is not enough to classify the article as subscription-only. Record OA status as unknown unless an explicit indicator establishes it.

## Other ego-tested routes

These observations establish the tested papers and reused sessions, not all journals or subscription coverage. Keep exact paper identities and environment details in local run records.

| Platform | Demonstrated behavior affecting the workflow |
| --- | --- |
| Elsevier / ScienceDirect | Direct canonical pages on a user-reported campus network recognized the institution and exposed full text without a new login or WebVPN navigation. A visible Turnstile checkbox was clicked once through ego and the article became accessible. A non-OA article with reserved-rights evidence passed browser download and file checks. View PDF opens a native viewer on `pdf.sciencedirectassets.com`; wait for its actual Download control before saving. An initial viewer loading limit can expire before the document finishes loading; inspect that same viewer before retrying. Existing-profile success does not isolate IP authorization from retained publisher authentication. |
| Nature | A visible Download PDF link produced a download event directly. Hidden duplicate PDF links can exist; use the current visible control rather than a fixed first match. Four early accepted articles linked to `*_reference.pdf` while `citation_pdf_url` named another address. Their actual PDFs were readable articles marked Article in Press; record that version and verify content rather than rejecting or accepting from the URL suffix. |
| Springer Link | An initial subscription preview reached the school's CARSI form. After the user reported authentication, the original space was missing; an explicitly authorized replacement reused the same profile and showed article-specific school-provided access. Its visible Download PDF produced a direct download, and the non-OA paper passed all checks. This establishes one retained institutional session, not a fresh-login test or universal journal coverage. Inspect current access before repeating login. |
| Wiley / AGU | Article access options and a completed security check are separate from PDF entitlement. Two JGR articles initially exposed purchase/institution options; after the user changed their external proxy condition, the same profile showed institutional Full Access and both files passed checks. This comparison does not establish a universal network cause or require other users to change their network. Article/reader PDF links opened new tabs and did not yield an event on the article Page. The successful route used the observed `/doi/epdf/<DOI>` reader's format-menu `/doi/pdfdirect/<DOI>?download=true` link: arm capture on its actual destination Page, navigate, then save in the same round. `ERR_ABORTED` can accompany a real download; verify the artifact. Institution identity, portal gaps and exact papers belong in the local run record. `Free Access` alone is not an open license. |
| ACS | The visible article PDF link opened a native viewer popup, whose Download control saved the PDF. Search markup also contained hidden inputs; select the rendered search field from current page evidence. |
| Copernicus | Article PDF navigated to the browser viewer; a large viewer was still loading after the first wait. Native collection once waited for a manual Save As confirmation; three other loaded viewers saved with serialized SDK capture without that intervention. A later eight-paper native batch reached a deliberately configured four-minute diagnostic ceiling with growing transfers and no completed file; this is a partial diagnostic result, not idle failure or evidence that the historical viewer route stopped working. A later measurement of one prepared PDF (`10.5194/se-17-991-2026`, 14.8 MB) read `206` with `Content-Range` from the browser at about 330 KB/s, while the same host from a plain client measured 14 KB/s minutes earlier and answered TCP/TLS slowly (1.3 s / 2.1 s). Expect roughly a minute per file alone and several minutes when eight run together; treat slow-but-growing transfers as a concurrency budget problem rather than a refusal. A later retest completed 8 of 8 previously missing PDFs at concurrency 3 (5-26 MB each) using the article's observed PDF URL and the native viewer: the viewer's load was the transfer, and the viewer's Download control then saved from cache in 83-1860 ms. Size the budget to the viewer load. Use the stage-specific [viewer recovery](pdf-viewer-recovery.md), rather than repeated article clicks. |
| MDPI / Frontiers | Visible PDF links produced direct downloads. For an isolated SDK capture, arm the wait before clicking. For requested concurrent work, the [shared record pool](batch-download-tools.md#shared-pool-for-independent-workers) collected actual completed browser records without SDK download objects. A historical concurrent SDK save produced the wrong paper despite its expected filename; that failure is distinct from shared-pool collection and still requires content verification. A later bounded measurement of one MDPI PDF returned `206` with Range honored at 56-74 KB/s, so an interrupted MDPI file of several MB is a throughput-and-duration outcome, not a refusal. A later retest found four MDPI article PDFs of 6.9, 28.5, 40.9 and 48.5 MB: three at a time were truncated to 20-44% while `download.saveAs()` still resolved without error, and the same files downloaded one at a time completed at 415-425 KB/s. Prefer one MDPI download at a time for large files, and compare the saved size with the server's declared total. The article page also carries a publisher flyer PDF, so a generic `.pdf` selector can pick the wrong file; use the article's own `/pdf` URL. |
| PLOS | Resolve an actual consent overlay before clicking. Download PDF can open a short-lived tab whose native event is lost. The current shared pool collected four such papers in the 24-paper test from new completed browser records, then verified their content. A later eight-paper test collected six natively; two instead remained in loaded PDF readers and were saved sequentially through SDK capture. Inspect the actual destination before selecting intake or viewer recovery. Preserve each route's actual completion evidence, not a fabricated native event. |
| PeerJ | The article Download button opens a modal containing the actual `/articles/<id>.pdf` link. Inspect the current modal and arm the browser download event before clicking that observed link; save in the same round, then verify file size and PDF identity. After the Ego Lite update to `0.6.1.13`, a serial retest completed three papers (4.9 MB, 17.5 MB and 28.8 MB), including two papers that had previously interrupted; a separate 33.7 MB paper also completed. A shared-pool retest of `10.7717/peerj.21792` opened the modal and clicked the observed PDF link through `triggerPoolDownload`, collected one new completed downloads-page record, copied 18,400,523 bytes, and matched the DOI/title with 25 pages. Allow minutes for larger files and do not infer denial from the old interrupted records. Continue controls are not proof of byte-range resume; preserve repeated-denial evidence and stop only when the current route actually repeats a denial. Both the single-paper SDK route and the shared-pool adapter are validated on `0.6.1.13`; the shared-pool result is still one-paper evidence, not a general concurrency guarantee. |
| OUP / Silverchair | For the tested GJI open-access route, the article's observed PDF link redirects to the Silverchair PDF reader. Wait for the reader's page count, arm the download event before clicking its visible Download control, and save in the same round. After the Ego Lite update to `0.6.1.13`, two new papers completed serially: 20 pages / 9.7 MB and 40 pages / 35.6 MB; the earlier 17-page / 78.6 MB paper also completed. One new article first showed a Cloudflare waiting page and auto-passed within the bounded wait; the other opened directly. The PDF text exposes OUP's article identifier suffix, so strict DOI matching may be false while title/identity and visual checks pass. The host ignores Range in earlier diagnostics, so an interruption can cost the full transfer; budget the reader load and preserve the route evidence. This validates the tested GJI OA path, not every OUP journal or entitlement state. |
| IOP | After user verification, an article PDF link opened a native viewer popup. Saving from its Download control worked. The PDF included a publisher cover; inspect the article's first page as well as the cover and count all PDF pages. |
| Taylor & Francis | An earlier enhanced-reader attempt reached a PDF/EPUB menu and then a verification challenge without a saved file. A later OA test of `10.1080/08120099.2024.2319105` succeeded: the reader's PDF-menu click produced no download event, but normal navigation to its observed PDF href, with a download wait armed, yielded a same-round SDK save. The 16-page file (publisher cover plus 15 article pages) passed DOI/title and cover/article-first-page visual checks. This reused-profile OA result does not prove subscription access or fresh authentication. |

## Untested routes and capability claims

Start from the visible article and access controls. Do not claim support until a PDF has been downloaded and checked. Keep a publisher note only when it contains a demonstrated behavior that changes the workflow.

InstSci publisher catalogs, matrices, selectors, and old successes can suggest where to look. They do not transfer CloakBrowser capability verdicts, login state, signed links, or API calls into ego. Adapt browser actions using the current ego guide and record new evidence before adding an ego-tested route here.

Publisher pauses and previous run evidence belong in the user's task record. Do not turn a session-specific restriction or a previously validated session into a general capability claim.

## Executable route policy

Workers that need a deterministic first action can import
[`scripts/publisher_route_policy.mjs`](../scripts/publisher_route_policy.mjs). The
pure `publisherRoute(name, {viewerLoaded})` helper does not navigate or capture
anything; it records the route decision that the worker must then execute with
the normal ego and shared-pool rules. Copernicus and ACS deliberately return
`wait_for_viewer_then_observe_download` until the current viewer's Download
control has been observed. MDPI and Frontiers select the article PDF URL and
shared browser-record collection, with MDPI's large-file policy requiring a
server byte total. An unknown publisher returns `route_status: unsupported`
instead of silently using a generic selector.
